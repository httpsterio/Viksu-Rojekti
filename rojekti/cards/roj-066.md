## Overview

Replace `isDarkMode: boolean` with a proper multi-theme system. Four themes: `sane`, `sane-dark`, `whimsical`, `whimsical-dark`. Each is a fully standalone PrimeVue preset — no light/dark duality within a single preset, each theme defines its own complete set of tokens.

Component anatomy stays as-is. What changes is visual personality: colors, radius, shadow, spacing, typography.

## Themes

| Name | Description |
|------|-------------|
| `sane` | Default light theme, close to Aura |
| `sane-dark` | Dark variant of sane |
| `whimsical` | Distinctive light theme, personality TBD |
| `whimsical-dark` | Dark variant of whimsical |

## File structure

```
src/
  themes/
    aura-base.ts        ← owned copy of Aura preset source (pulled from GitHub tag 4.5.4, done manually)
    index.ts            ← maps theme name string to preset + metadata
    sane.ts
    sane-dark.ts
    whimsical.ts
    whimsical-dark.ts
  styles/
    fonts.css           ← @font-face declarations, imported per-theme as needed
    themes.css          ← [data-theme="x"] CSS overrides for anything tokens can't reach
    main.css            ← existing, add imports for fonts.css and themes.css
```

## Startup (no flash)

In `main.ts`, fetch board state before mounting and initialize PrimeVue with the correct preset from the start. Do not mount first and fix later.

```typescript
import { invoke } from '@tauri-apps/api/core'
import { getPreset } from '@/themes'
import type { BoardState } from '@/types'

const boardState = await invoke<BoardState>('get_board_state')
  .catch(() => ({ theme: 'sane' } as BoardState))

const app = createApp(App)
app.use(PrimeVue, {
  theme: {
    preset: getPreset(boardState.theme),
    options: { darkModeSelector: false }
  }
})
document.documentElement.setAttribute('data-theme', boardState.theme)
app.mount('#app')
```

`darkModeSelector: false` — Aura's built-in light/dark switching is disabled. Each theme is fully self-contained.

Runtime theme changes call `updatePreset(newPreset)` from `@primevue/themes`.

## src/themes/index.ts

```typescript
import type { PrimeVueConfiguration } from 'primevue/config'
import sane from './sane'
import saneDark from './sane-dark'
import whimsical from './whimsical'
import whimsicalDark from './whimsical-dark'

export const themes: Record<string, { preset: PrimeVueConfiguration['theme']['preset'], isDark: boolean }> = {
  'sane':           { preset: sane,         isDark: false },
  'sane-dark':      { preset: saneDark,     isDark: true  },
  'whimsical':      { preset: whimsical,    isDark: false },
  'whimsical-dark': { preset: whimsicalDark, isDark: true },
}

export function getPreset(name: string) {
  return themes[name]?.preset ?? themes['sane'].preset
}
```

## useBoard.ts migration

Remove `isDarkMode: ref<boolean>` and `toggleDarkMode`. Replace with:

```typescript
const currentTheme = ref<string>('sane')

// Derived — used by contrast utilities and any component that needs to know
const isDark = computed(() => themes[currentTheme.value]?.isDark ?? false)

const setTheme = (name: string) => {
  if (!themes[name]) return
  currentTheme.value = name
  updatePreset(themes[name].preset)
  document.documentElement.setAttribute('data-theme', name)
}
```

`isDark` replaces all existing references to `isDarkMode` in components and composables. It is read-only — you cannot set dark mode directly, only by selecting a dark theme.

Update `loadBoard` to call `setTheme(boardState.theme)` instead of the old dark mode logic. The `stateLoaded` guard still applies.

Update `saveState` to save `currentTheme.value` instead of `isDarkMode.value ? 'dark' : 'light'`.

Update `watch` to use `() => currentTheme.value`.

## CSS side overrides

Use `[data-theme]` attribute on `<html>`. Do not use class toggling — it clobbers other classes.

```css
/* src/styles/themes.css */
[data-theme="sane"] {
  /* existing --bg-primary, --text-primary etc. migrate here */
}

[data-theme="sane-dark"] {
  /* existing .dark-mode variables migrate here */
}
```

The existing `:root` and `.dark-mode` variable blocks in `main.css` move into `themes.css` as the `sane` and `sane-dark` entries respectively. The `.dark-mode` class can be removed once migrated.

## Custom fonts

Per-theme fonts are defined in `fonts.css` and assigned to `--p-font-family` inside the theme's `[data-theme]` block in `themes.css`. Components inherit via `font-family: var(--p-font-family, sans-serif)`. Only fonts for installed themes need to be loaded.
