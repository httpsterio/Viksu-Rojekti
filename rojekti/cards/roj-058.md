* The Bug: While editing Epic or Tag names in the Board Settings modal, the input field would lose
     focus after every single keystroke, making typing impossible. Additionally, the previous attempt to
     fix this using @change resulted in stale data being reverted if the user typed in the middle of a
     string.

   * The Cause:
       * The v-for loops for Epics and Tags used epic.name and tag.name as the :key.
       * Since these entities lack stable unique IDs in the current schema, renaming them changed their
         identity (the key) immediately.
       * Vue reacted by destroying and recreating the DOM element for that item, which naturally dropped
         the focus and cursor position.

   * The Solution:
       * Stable Keys: Switched the :key for Epics and Tags from name to the array index.
       * Reverted to v-model: Once the key was stabilized via the index, v-model could be safely used
         again without triggering component recreation.
       * Safe Deletions: Simplified the removeEpic and removeTag functions to take the index directly,
         avoiding indexOf lookups.

   * Why this is the optimal fix:
       * UX: It restores the standard "type-as-you-go" behavior without focus loss.
       * Simplicity: It matches the pattern already used successfully for Priorities in the same modal.
       * Safety: It avoids adding "synthetic" IDs to the frontend that would need to be stripped before
         saving to the backend (preventing schema pollution).
