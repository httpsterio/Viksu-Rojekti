## Overview

Add an optional `due_date` field to cards. Cards with a due date show a colored right-side border on the board: yellow if due within the configured threshold, red if overdue. Done cards are never highlighted. The threshold is a user-configurable number of days stored in `rojekti.config.yaml`, defaulting to 7.

`due_date` is intentionally separate from a future `completed_date` field (roj-074). This ticket covers only `due_date`.

## Data model

### CardMeta (`src-tauri/src/models.rs`)

```rust
#[serde(skip_serializing_if = "Option::is_none")]
pub due_date: Option<String>,
```

Stored as an ISO date string (`YYYY-MM-DD`). Absent from YAML when not set. Follow the existing snake_case/camelCase pattern already established in `CardMeta`.

### BoardConfig (`src-tauri/src/models.rs`)

```rust
#[serde(default = "default_due_date_threshold")]
pub due_date_threshold: u32,

fn default_due_date_threshold() -> u32 { 7 }
```

Written to `rojekti.config.yaml`. Absent from existing configs will default to 7 via `serde(default)`.

## TypeScript types (`src/types/index.ts`)

```ts
// CardMeta
dueDate?: string

// BoardConfig
dueDateThreshold: number
```

## Card.vue (board surface)

Add a right-side border that reflects due date status. The card already uses `border-left` for priority — add `border-right: 4px solid transparent` as the default, then drive its color via a computed.

```ts
const dueDateBorderColor = computed(() => {
  if (!props.card.dueDate || isDone.value) return 'transparent'
  const today = new Date()
  today.setHours(0, 0, 0, 0)
  const due = new Date(props.card.dueDate)
  const diffDays = Math.ceil((due.getTime() - today.getTime()) / (1000 * 60 * 60 * 24))
  const threshold = config.value?.dueDateThreshold ?? 7
  if (diffDays < 0) return '#E53E3E'   // overdue — red
  if (diffDays <= threshold) return '#ECC94B'  // due soon — yellow
  return 'transparent'
})
```

Bind in template alongside the existing priority border:

```html
:style="{
  borderLeftColor: ...,
  borderRightColor: dueDateBorderColor,
}"
```

`isDone` is already computed from `doneStatusNames` — no new logic needed for the done check.

## CardModal.vue

### Import

```ts
import DatePicker from "primevue/datepicker"
```

### Local state

The `DatePicker` component works with a `Date` object, but storage uses an ISO string. Use a local ref that converts on the way in and out:

```ts
const dueDateObj = computed({
  get: () => card.value.dueDate ? new Date(card.value.dueDate) : null,
  set: (val: Date | null) => {
    card.value.dueDate = val ? val.toISOString().split('T')[0] : undefined
  }
})
```

### Template placement

Add after Tags, before Checklist, in the left metadata column:

```html
<div class="field">
  <label>Due Date</label>
  <DatePicker
    v-model="dueDateObj"
    date-format="yy-mm-dd"
    placeholder="No due date"
    show-clear
    fluid
  />
</div>
```

`show-clear` allows removing the date once set.

### Initial card state

Add `dueDate: undefined` to `getInitialCard()`.

## commands.rs

Two changes required:

**`create_card`** — add `due_date: Option<String>` as a parameter and pass it into the `CardMeta` initializer.

**`init_project`** — constructs `BoardConfig` directly. Once `due_date_threshold` is added to the struct, this will fail to compile unless `due_date_threshold: 7` is added to that initializer too.

## Implementation notes

### Timezone handling
`toISOString()` returns UTC time, so a user in UTC+2 picking March 30 would have saved March 29. Similarly, `new Date("YYYY-MM-DD")` parses as UTC midnight, causing the DatePicker to display the wrong day for users behind UTC.

Both `CardModal.vue` and `Card.vue` parse and format dates using local time components instead:

```ts
// parsing
const [y, m, d] = dateStr.split('-').map(Number)
new Date(y, m - 1, d)  // local midnight

// formatting
`${val.getFullYear()}-${String(val.getMonth() + 1).padStart(2, '0')}-${String(val.getDate()).padStart(2, '0')}`
```

### cli.rs
`cli.rs` also constructs `CardMeta` and `BoardConfig` directly and required the same `due_date: None` and `due_date_threshold: 7` additions as `commands.rs`.
