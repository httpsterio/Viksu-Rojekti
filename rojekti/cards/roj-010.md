## Overview

Cards can have files attached to them. Attachments are either **copied** into the local
`rojekti/attachments/` folder or **linked** by storing a reference to wherever the file lives on
disk. The mode is a global board setting; it applies to new attachments only — existing ones are
not retroactively migrated when the setting changes.

Supported attachment types have three display behaviours:
- **Images** (jpg, jpeg, png, gif, webp, svg): rendered as a thumbnail inline in the card.
- **Audio** (mp3, wav, ogg, flac, m4a): rendered with an HTML5 `<audio>` player inline.
- **Video** (mp4, webm): rendered with an HTML5 `<video>` player inline.
- **Everything else** (pdf, docx, xlsx, fig, zip, etc.): a button that opens the file in the
  OS default application.

## Project Structure Reference

Refer to `GEMINI.md` for the full project conventions. Key points:
- All structs in `models.rs`. All file I/O in `storage.rs`. Commands in `commands.rs`.
- All state in `composables/useBoard.ts`. Components never call `invoke()` directly.
- Error handling: always `Result<T, String>`. No `unwrap()` in command handlers.
- Do not use `tauri-plugin-opener` — it has caused build failures. Use a custom Rust command
  instead (see Step 5).
- Do not use the Tauri filesystem plugin.

## Filename Convention (Copied Files)

When a file is copied into `rojekti/attachments/`, the filename is constructed as:

```
{CARD_ID}_{truncated_base_name}{.ext}
```

Rules:
1. Truncate the base name (without extension) to **50 characters**.
2. Preserve the original extension as-is.
3. If the resulting filename already exists in `rojekti/attachments/`, append a 4-character
   random hex suffix before the extension: `ROJ-001_screenshot_a3f9.png`.
4. Repeat with a new random suffix until no collision.

## Implementation Steps

### Step 1 — Update `models.rs`

Add the `Attachment` struct, `AttachmentMode` enum, the `attachments` field to `CardMeta`, and
the `attachment_mode` field to `BoardConfig` as shown in the data model section above.

### Step 2 — Update `storage.rs`

Add two helper functions:

**`copy_attachment`**: copies a source file into `rojekti/attachments/` using the naming
convention above. Returns the final `PathBuf` of the copied file.

```rust
pub fn copy_attachment(project_dir: &Path, card_id: &str, source_path: &Path) -> Result<PathBuf, String>
```

Logic:
1. Extract the base name and extension from `source_path`.
2. Truncate base name to 50 chars.
3. Construct candidate filename: `{card_id}_{base}.{ext}`.
4. Check if `rojekti/attachments/{candidate}` exists. If so, append 4-char hex: loop until free.
5. `fs::create_dir_all(rojekti/attachments/)`.
6. `fs::copy(source_path, dest_path)`.
7. Return `dest_path`.

**`move_card_attachments_to_deleted`**: called when a card is deleted. Moves any attachment files
whose paths are inside `rojekti/attachments/` into `rojekti/attachments/deleted/`. Linked files
(paths outside `rojekti/attachments/`) are ignored.

```rust
pub fn move_card_attachments_to_deleted(project_dir: &Path, attachments: &[Attachment]) -> Result<(), String>
```

Logic:
1. Construct the canonical local attachments path: `project_dir/rojekti/attachments/`.
2. For each attachment, check if its `path` starts with the local attachments path.
3. If yes: `fs::create_dir_all(rojekti/attachments/deleted/)`, then `fs::rename(src, deleted/filename)`.
4. If no (linked file): skip entirely.

### Step 3 — Update `commands.rs`: new commands

**`add_attachment`**

```rust
#[tauri::command]
pub fn add_attachment(
    card_id: String,
    source_path: String,
    state: State<AppState>,
) -> Result<Attachment, String>
```

Logic:
1. Acquire `write_lock` and stamp `last_gui_write`.
2. Read `BoardConfig` to check `attachment_mode`.
3. If `Copy`: call `storage::copy_attachment(...)` to get the dest path. Set `path = dest_path`,
   `name = original_filename`.
4. If `Link`: use `source_path` as-is. Set `path = source_path`, `name = filename_from_path`.
5. Read the card, push the new `Attachment` to `card.meta.attachments`, write the card back.
6. Rebuild index.
7. Return the new `Attachment`.

**`remove_attachment`**

```rust
#[tauri::command]
pub fn remove_attachment(
    card_id: String,
    attachment_path: String,
    state: State<AppState>,
) -> Result<(), String>
```

Logic:
1. Acquire `write_lock` and stamp `last_gui_write`.
2. Read the card, remove the attachment matching `attachment_path` from `card.meta.attachments`.
3. Check if the removed path is inside `rojekti/attachments/` — if yes, delete the file with
   `fs::remove_file`. If no (linked), leave the original file alone.
4. Write the card back. Rebuild index.

**`open_file`** — opens a file in the OS default application (replaces `tauri-plugin-opener`):

```rust
#[tauri::command]
pub fn open_file(path: String) -> Result<(), String>
```

```rust
#[cfg(target_os = "windows")]
fn open_default(path: &str) -> Result<(), String> {
    std::process::Command::new("cmd")
        .args(["/C", "start", "", path])
        .spawn()
        .map_err(|e| format!("Failed to open file: {}", e))?;
    Ok(())
}

#[cfg(target_os = "macos")]
fn open_default(path: &str) -> Result<(), String> {
    std::process::Command::new("open")
        .arg(path)
        .spawn()
        .map_err(|e| format!("Failed to open file: {}", e))?;
    Ok(())
}

#[cfg(target_os = "linux")]
fn open_default(path: &str) -> Result<(), String> {
    std::process::Command::new("xdg-open")
        .arg(path)
        .spawn()
        .map_err(|e| format!("Failed to open file: {}", e))?;
    Ok(())
}

pub fn open_file(path: String) -> Result<(), String> {
    open_default(&path)
}
```

### Step 4 — Update `commands.rs`: update `delete_card`

Before deleting the card file, read the card and move its local attachments to
`rojekti/attachments/deleted/`:

```rust
#[tauri::command]
pub fn delete_card(id: String, state: State<AppState>) -> Result<(), String> {
    let _lock = state.write_lock.lock().map_err(|e| format!("Lock error: {}", e))?;
    *state.last_gui_write.lock().map_err(|e| format!("Lock error: {}", e))? = std::time::Instant::now();

    // Read card first to get attachments before deleting
    let card_path = state.project_dir.join("rojekti").join("cards").join(format!("{}.md", id));
    let card = storage::read_card(&card_path)?;
    storage::move_card_attachments_to_deleted(&state.project_dir, &card.meta.attachments)?;

    storage::delete_card_file(&state.project_dir, &id)?;
    index::rebuild_index(&state.project_dir)?;
    Ok(())
}
```

### Step 6 — Configure Tauri asset protocol scope (`tauri.conf.json`)

For the frontend to render local images/audio/video using `convertFileSrc`, the Tauri asset
protocol needs permission to access the attachments directory. Since the path is dynamic
(relative to the executable), configure a broad scope and/or add the path at runtime in `setup()`:

In `tauri.conf.json`:
```json
"app": {
  "security": {
    "assetProtocol": {
      "enable": true,
      "scope": ["**"]
    }
  }
}
```

Alternatively, scope it more tightly in `setup()` at runtime using:
```rust
app.asset_protocol_scope().allow_directory(&attachments_dir, true);
```

Note: `convertFileSrc` from `@tauri-apps/api/core` converts an absolute file path to a
`asset://localhost/...` URL that the webview can load. Use this for all inline image/audio/video
rendering.

### Step 7 — Add attachment UI to `CardModal.vue`

The attachment section lives below the description editor in `CardModal.vue`. It is only shown
when a card is open (not during initial card creation — attachments can be added after saving).

**Display existing attachments:**

- Determine type from file extension.
- **Image**: `<img>` with `src="convertFileSrc(attachment.path)"`. Show filename below. Button

- **Audio**: `<audio controls>` with `src="convertFileSrc(attachment.path)"`. Filename label.

- **Video**: `<video controls>` with `src="convertFileSrc(attachment.path)"`. Filename label.
  Button to remove.
- **Other**: A row showing the filename and a "Open" button (`invoke('open_file', { path })`).
  Button to remove.
- **Missing file** (path does not exist — detected via a Rust command or noted in attachment

**Adding attachments:**

A button ("Add attachment") opens a file picker dialog using Tauri's dialog plugin:

Also implement a drag-and-drop zone over the attachment area using the HTML5 `drop` event or

### Step 9 — Update `useBoard.ts`

Add the following methods and expose them from `useBoard()`:

```typescript
const addAttachment = async (cardId: string, sourcePath: string) => {
    const attachment = await invoke<Attachment>('add_attachment', { cardId, sourcePath })
    const card = cards.value.find(c => c.id === cardId)
    if (card) card.attachments.push(attachment)
}

const removeAttachment = async (cardId: string, attachmentPath: string) => {
    await invoke('remove_attachment', { cardId, attachmentPath })
    const card = cards.value.find(c => c.id === cardId)
    if (card) card.attachments = card.attachments.filter(a => a.path !== attachmentPath)
}

const openFile = async (path: string) => {
    await invoke('open_file', { path })
}

const checkAttachment = async (path: string): Promise<boolean> => {
    return await invoke<boolean>('check_attachment', { path })
}
```

## File Type Classification Reference

Use file extension to determine display behaviour. Check extension in the frontend (lowercase,
strip the leading dot).

| Category | Extensions |
|---|---|
| Image | jpg, jpeg, png, gif, webp, svg |
| Audio | mp3, wav, ogg, flac, m4a |
| Video | mp4, webm |
| Other (open in default app) | Everything else — pdf, docx, xlsx, pptx, fig, zip, etc. |

Video and audio formats not listed (e.g. mkv, avi, mov) fall into "Other" and open via the
default app handler.

## Behaviour Summary

| Action | Result |
|---|---|
| Add attachment, mode = Copy | File copied to `rojekti/attachments/ROJ-XXX_name.ext`. Card frontmatter updated. |
| Add attachment, mode = Link | Path stored as-is. Nothing copied. Card frontmatter updated. |
| Remove attachment (local) | File deleted from `rojekti/attachments/`. Reference removed from frontmatter. |
| Remove attachment (linked) | Original file left untouched. Reference removed from frontmatter. |
| Delete card | Local attachments moved to `rojekti/attachments/deleted/`. Linked files left alone. |
| Open non-inline file | OS default app launched via platform-specific `std::process::Command`. |
| Missing file detected | "⚠ File not found" shown with option to remove reference. |
| Switch attachment mode in settings | Only affects future attachments. Existing ones unchanged. |

## Follow-up Feature: Smart Path Healing (Not in Scope for This Pass)

When a project folder is moved, local attachment paths (which are absolute) will break. A future
enhancement should:

1. On app startup or board load, for each attachment whose path starts with
   `{some_prefix}/rojekti/attachments/` but does not match the current
   `{project_dir}/rojekti/attachments/`: assume the project was moved.
2. Check if `{project_dir}/rojekti/attachments/{filename}` exists.
3. If yes: silently update the path in the frontmatter to the new correct absolute path.
4. If no: fall through to the normal "file not found" indicator.

This avoids the entire attachment library going missing when a user moves their project folder.
Linked files (outside `rojekti/attachments/`) are never healed — the user owns that path.

## What Not to Do

- Do not add `tauri-plugin-opener`. Use the custom `open_file` command instead.
- Do not create `rojekti/attachments/` during `init_project`. Create it on first use.
- Do not show the attachment UI during initial card creation — only on existing cards.
- Do not migrate existing attachments when the user toggles the attachment mode setting.
- Do not delete original files for linked attachments under any circumstance.
- Do not use `any` in TypeScript.
- Do not add comments explaining what code does — only comment the "why" when non-obvious.
