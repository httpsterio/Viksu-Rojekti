Drag-and-drop reordering of statuses, epics, and tags in `BoardSettingsModal.vue` does not work correctly. Dragging an item either snaps back to its original position, fails to start, or produces flickering.

## Root cause

`BoardSettingsModal.vue` initializes drag-and-drop twice on the same DOM elements:

1. `useDragAndDrop` (lines 23–25) — the Vue composable, which internally calls `dragAndDrop` and attaches event listeners when the parent ref is mounted.
2. A manual `dragAndDrop([...])` call inside the `watch(visible, ...)` block — called again after `nextTick` every time the dialog opens.

Two separate DnD instances are attached to the same parent elements, competing for pointer events. The configuration (dragHandle, plugins, onSort) is only passed to the second instance, leaving the first one unconfigured and partially in control.

## What is not the bug

The `v-for` keys using `:key="index"` are intentional — they were changed from `:key="epic.name"` to fix a separate issue where typing in an input field caused Vue to destroy and recreate the element on every keystroke, ejecting focus. This should not be reverted.

## Fix

1. **Removed `useDragAndDrop`** — the Vue hook uses a one-time internal watch that fires when the parent ref is first bound, then calls `stop()`. On dialog close, PrimeVue unmounts the content. On reopen, the ref binds to a new element but the watch is dead — DnD never reinitializes. Replaced with plain refs.

2. **Explicit lifecycle in `watch(visible)`** — on open: set values, await nextTick, call `dragAndDrop()` with the actual element. On close: call `tearDown()`. Matches Lane.vue's pattern.

3. **Stable `_dragId` keys** — index keys caused Vue to patch DOM nodes in place during drag rather than move them, fighting formkit's own DOM manipulation. A temporary `_dragId` is added to each item on load, used as the `:key`, and stripped at save time.

4. **`nativeDrag: true`** — aligns with Lane.vue; the browser manages cursor state consistently through its native DnD API.

5. **`@dragover.capture.prevent @dragenter.capture.prevent` on parent containers** — the `gap` between list items (and text inputs inside items) were dead zones where the browser showed the stop-sign cursor. Capture-phase handlers on the parents ensure `preventDefault()` is always called before any child's native behavior can interfere.
