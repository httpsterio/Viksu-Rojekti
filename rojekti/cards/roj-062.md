Drag-and-drop reordering of statuses, epics, and tags in `BoardSettingsModal.vue` does not work correctly. Dragging an item either snaps back to its original position, fails to start, or produces flickering.

## Root cause

`BoardSettingsModal.vue` initializes drag-and-drop twice on the same DOM elements:

1. `useDragAndDrop` (lines 23–25) — the Vue composable, which internally calls `dragAndDrop` and attaches event listeners when the parent ref is mounted.
2. A manual `dragAndDrop([...])` call inside the `watch(visible, ...)` block — called again after `nextTick` every time the dialog opens.

Two separate DnD instances are attached to the same parent elements, competing for pointer events. The configuration (dragHandle, plugins, onSort) is only passed to the second instance, leaving the first one unconfigured and partially in control.

## What is not the bug

The `v-for` keys using `:key="index"` are intentional — they were changed from `:key="epic.name"` to fix a separate issue where typing in an input field caused Vue to destroy and recreate the element on every keystroke, ejecting focus. This should not be reverted.
