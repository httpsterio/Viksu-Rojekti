## Problem

Tags and epics have user-defined background colors. Text rendered on top of those colors is currently either hardcoded to `white` (`Card.vue`) or unset (`CardModal.vue`), meaning dark-colored tags get dark text and light-colored tags get white text — both potentially unreadable.

The logic is duplicated across files and inconsistent:

| File | Where | Current behavior |
|------|-------|-----------------|
| `Card.vue` | `getTagStyle()` | `color: 'white'` always |
| `Card.vue` | epic badge | no text color set |
| `CardModal.vue` | removable tag chips | no text color set |
| `BoardSettingsModal.vue` | tag/epic previews | no text color set |

## Solution

A single composable `useColorContrast` in `src/composables/useColorContrast.ts` that exposes one function: `contrastColor(hex)`. Any component that renders colored badges imports and uses it.

---

## Implementation

### `src/composables/useColorContrast.ts`

```ts
export function useColorContrast() {
  function contrastColor(hex: string): string {
    const r = parseInt(hex.slice(1, 3), 16)
    const g = parseInt(hex.slice(3, 5), 16)
    const b = parseInt(hex.slice(5, 7), 16)
    const luminance = (0.299 * r + 0.587 * g + 0.114 * b) / 255
    return luminance > 0.5 ? '#000000' : '#ffffff'
  }

  return { contrastColor }
}
```

The luminance formula is a standard perceptual weighting (ITU-R BT.601) — green contributes most to perceived brightness, then red, then blue. Values above `0.5` are light backgrounds → black text. Values at or below `0.5` are dark backgrounds → white text.

### Fallback behavior

If `hex` is undefined, null, or not a valid 7-character hex string, `contrastColor` should return `'#000000'` rather than throw. Guard at the top of the function:

```ts
if (!hex || hex.length < 7) return '#000000'
```

---

## Usage in Components

Import once per component:

```ts
import { useColorContrast } from '@/composables/useColorContrast'
const { contrastColor } = useColorContrast()
```

Then inline on any colored element:

```vue
:style="{ backgroundColor: tag.color, color: contrastColor(tag.color) }"
```

## Files to Update

### `Card.vue`

- `getTagStyle()`: replace `color: 'white'` with `color: contrastColor(tag.color)`
- Epic badge: add `color: contrastColor(epic.color)` alongside the existing `backgroundColor`

### `CardModal.vue`

- Removable tag `<Tag>` chips: add `color: contrastColor(getTag(tagId)?.color)` to the existing `:style` binding
- Guard for missing color: the `getTag()` call can return undefined, so only call `contrastColor` if color exists

### `BoardSettingsModal.vue`

- Any tag or epic preview elements that show the color with text on top should apply the same pattern

---

## What Not to Do

- Do not put `contrastColor` directly in `useBoard` — it is a pure UI utility with no dependency on board state
- Do not inline the luminance calculation in components — always import from the composable
- Do not handle non-hex color formats (rgb, hsl, named colors) — all colors in this app come from `<input type="color">` which always produces 7-character hex strings (`#rrggbb`)
