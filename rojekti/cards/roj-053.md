## Status

Blocked. `setDragImage` does not work in Tauri v2 / WebView2 on Windows — the drag ghost always uses the OS-rendered default regardless of what element is passed. This is a known WebView2 limitation.

The native drag ghost IS rendered from the card element with `dragging-card` class applied (CSS background-color, transform, box-shadow show up). Opacity cannot be controlled — the OS compositor applies it at a layer above CSS.

Current implementation: `transform: rotate(2deg)` and `box-shadow` on `.dragging-card`.

## Original Goal

When dragging a card with `nativeDrag: true`, the browser renders the ghost image using OS-level compositing, which applies reduced opacity and prevents any CSS styling. Use FormKit's `dragImage` config callback to provide a fully styled custom ghost element via `setDragImage()`.

## Behaviour

- The dragged ghost should appear fully opaque
- It should have an elevated box-shadow to give a "lifted" feel
- A slight rotation (1–2deg) gives a natural picked-up feel
- The ghost dimensions should match the original card exactly
- The original card's position in the list shows the green dashed landing zone placeholder (already implemented via `ghost-card`)

## Implementation

FormKit's `dragImage` config accepts `(data: NodeDragEventData<T>, draggedNodes: Array<NodeRecord<T>>) => HTMLElement`. The returned element is passed to `dataTransfer.setDragImage()`.

Steps:
1. In the `dragImage` callback, clone the dragged card's DOM element
2. Apply styles to the clone: `opacity: 1`, `rotate: 2deg`, elevated `box-shadow`, `position: fixed`, `top: -9999px` (offscreen so browser captures it but it's not visible in the layout)
3. Append the clone to `document.body` so `setDragImage` can read it
4. Clean up the clone on `dragend` — store a ref to it and remove it from the DOM

## Constraints

- `setDragImage` requires the element to be in the DOM at call time, but it can be removed immediately after (the browser takes a snapshot)
- FormKit's `dragImage` callback fires before `setDragImage` is called internally, so the element must be returned synchronously
- Cleanup must happen in `onDragend` to avoid DOM leaks
- No `any` types
