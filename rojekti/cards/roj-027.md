## Overview

Cards can reference other cards. There are two ways to add a link and one source of truth.

## Storage

`links: string[]` added to `CardMeta` — a list of card IDs stored in the frontmatter:

```yaml
links:
  - roj-012
  - roj-034
```

## Two ways to link

**1. Inline markdown**

Writing `[[prefix-number]]` anywhere in the card body (e.g. `[[roj-042]]`, `[[myproject-1234]]`) renders as a styled inline chip with a card icon. The prefix is not hardcoded — the markdown-it plugin matches any `[[letters-digits]]` pattern using `\[\[([a-zA-Z]+-\d+)\]\]`, supporting any project prefix and any number of digits.

At render time the matched ID is checked against the loaded cards. If the card exists → rendered as a clickable chip. If not → rendered as plain text, no broken link.

Clicking a valid chip opens that card's modal.

On save, the body is scanned for `[[prefix-number]]` patterns. Any IDs that match an existing card are merged into the `links` field — additive only. Removing a reference from markdown does not remove it from `links`.

**2. Linked cards field**

A dedicated section in the card modal below the body — a card search/selector (by ID or title). Adding a card here appends its ID to `links`. Removing it from the field removes it from `links`. Does not modify the markdown body.

## Navigation

Opening a linked card from within a card modal pushes it onto a navigation stack. Closing the linked card pops the stack and returns to the origin card. The back navigation is implicit — no visible breadcrumb needed, just the close action returns you to where you came from.

## Notes

- `links` is one-directional — it records what this card links to, not what links to it. Backlinks are a separate concern.
- The `links` field is optional and `skip_serializing_if` empty, so cards with no links remain unchanged on disk.
