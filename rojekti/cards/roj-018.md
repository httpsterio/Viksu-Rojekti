## Problem

Occasionally a newly created card would not appear on the board after saving, but would show up after a manual refresh (Ctrl+R).

## Root Cause

A race condition between `loadBoard` and the optimistic push in `createCard`. The sequence that triggers the bug:

1. `loadBoard()` is triggered (file watcher or concurrent call), dispatches `invoke('get_all_cards')` to Rust and awaits
2. User saves a new card — `createCard` runs, writes the card to disk, pushes it to `cards.value` optimistically — card appears
3. The in-flight `get_all_cards` from step 1 resolves — it was dispatched before the card was written, so Rust returned the list without the new card
4. `loadBoard` sets `cards.value = [stale list]` — overwrites the optimistic push, card disappears

## Fix

Added a `loadGeneration` counter at module level. Each `loadBoard` call captures the current generation and increments it. Before applying results, it checks whether its generation is still current. Stale loads discard their results silently.

```ts
let loadGeneration = 0

const loadBoard = async () => {
  const generation = ++loadGeneration
  // ...fetch...
  if (generation === loadGeneration) {
    config.value = newConfig
    cards.value = newCards
  }
}
```
