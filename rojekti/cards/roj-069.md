## Overview

Cards whose status is in `doneStatuses` (roj-055) should be visually distinct on the board. The treatment differs per theme but the implementation is shared.

## Implementation

Add a `doneStatusNames` computed to `useBoard.ts` — a `Set<string>` of status names derived from `config.doneStatuses` IDs joined through `config.statuses`. This is calculated once when config changes and shared across all card instances.

In `Card.vue`, add an `isDone` computed that does a single `.has()` lookup against `doneStatusNames`. Apply a `card-done` class to the card root element based on this.

Base styles for `card-done` live in `Card.vue`. Theme-specific overrides go in the theme CSS files, scoped via `[data-theme="..."] .card-done`. No JS branching between themes — CSS handles it entirely.

## Performance

Use only `transform` and `opacity` in animations — these are GPU-composited and don't trigger layout. Avoid animating `width`, `padding`, or `box-shadow` on done cards.

For off-screen cards: if looping animations cause measurable perf issues, use Intersection Observer to pause animations when cards leave the viewport (`animation-play-state: paused`). Collapsed lanes already don't render their card list so those are free.
