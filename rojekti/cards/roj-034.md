# Spec: Safe Epic/Tag Rename with Write-Ahead Log

## Overview

After migrating to name-based storage (`NAME_BASED_EPICS_TAGS_SPEC.md`), epics and tags are identified by name on card files. Renaming an epic or tag requires rewriting every card that references the old name. If this bulk operation is interrupted (crash, power loss), some cards will have the old name and some the new — a split state with no way to detect it.

This spec describes a write-ahead log (WAL) pattern using the config file to make renames recoverable.

**Dependency:** `NAME_BASED_EPICS_TAGS_SPEC.md` must be implemented first.

---

## Design

The config file acts as the WAL. Before touching any card files, the epic or tag entry in config is written with both the old and new name. This intermediate state signals "a rename is in progress". On next startup, the app detects this state and retries the rename automatically.

### Config intermediate state

Normal state:

```yaml
epics:
  - name: My Feature
    color: "#3b82f6"
```

During rename (WAL state):

```yaml
epics:
  - name: My Feature
    pendingRename: My New Feature Name
    color: "#3b82f6"
```

`name` = old name (still valid on existing card files)
`pendingRename` = new name (target)

### Recovery guarantee

- If the app crashes after writing the WAL config but before renaming any cards: on next start, all cards still have the old name. The WAL is detected, rename proceeds from scratch. Safe.
- If the app crashes mid-rename: on next start, cards with old name get renamed (idempotent), cards already renamed (have new name) are skipped (no match for old name — also safe). Then config is collapsed to new name.
- If the config collapse (step 3) fails: on next start, all cards have the new name already. The WAL is detected, rename runs but finds no cards matching the old name (idempotent), then collapses config. Safe.

## Implementation

### `src-tauri/src/models.rs`

Add `pending_rename` to `Epic` and `Tag`:

```rust
#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct Epic {
    pub name: String,
    pub color: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub pending_rename: Option<String>,
}

#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct Tag {
    pub name: String,
    pub color: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub pending_rename: Option<String>,
}
```

`skip_serializing_if = "Option::is_none"` ensures `pendingRename` only appears in the config during an active rename.

### `src-tauri/src/storage.rs` — rename function

```rust
pub fn rename_epic_or_tag(
    dir: &Path,
    config: &mut BoardConfig,
    is_epic: bool,
    old_name: &str,
    new_name: &str,
    config_path: &Path,
) -> Result<(), String> {
    // Step 1: Write WAL — mark the rename as in-progress in config
    {
        let entry = if is_epic {
            config.epics.iter_mut().find(|e| e.name == old_name)
        } else {
            config.tags.iter_mut().find(|t| t.name == old_name)
        };
        let entry = entry.ok_or_else(|| format!("'{}' not found", old_name))?;
        entry.pending_rename = Some(new_name.to_string());
    }
    write_board_config(config_path, config)?;

    // Step 2: Rename all card files
    apply_pending_renames(dir, config, config_path)?;

    Ok(())
}

pub fn apply_pending_renames(
    dir: &Path,
    config: &mut BoardConfig,
    config_path: &Path,
) -> Result<(), String> {
    // Collect all pending renames
    let epic_renames: Vec<(String, String)> = config.epics.iter()
        .filter_map(|e| e.pending_rename.as_ref().map(|new| (e.name.clone(), new.clone())))
        .collect();
    let tag_renames: Vec<(String, String)> = config.tags.iter()
        .filter_map(|t| t.pending_rename.as_ref().map(|new| (t.name.clone(), new.clone())))
        .collect();

    if epic_renames.is_empty() && tag_renames.is_empty() {
        return Ok(());
    }

    let (cards, _) = read_all_cards(dir)?;
    for card in cards {
        let mut updated = card.clone();
        let mut changed = false;

        if let Some(ref epic) = card.meta.epic {
            if let Some((_, new)) = epic_renames.iter().find(|(old, _)| old == epic) {
                updated.meta.epic = Some(new.clone());
                changed = true;
            }
        }

        let new_tags: Vec<String> = card.meta.tags.iter().map(|t| {
            tag_renames.iter()
                .find(|(old, _)| old == t)
                .map(|(_, new)| new.clone())
                .unwrap_or_else(|| t.clone())
        }).collect();
        if new_tags != card.meta.tags {
            updated.meta.tags = new_tags;
            changed = true;
        }

        if changed {
            write_card(dir, &updated)?;
        }
    }

    // Step 3: Collapse WAL — apply new names and clear pending_rename
    for epic in config.epics.iter_mut() {
        if let Some(new_name) = epic.pending_rename.take() {
            epic.name = new_name;
        }
    }
    for tag in config.tags.iter_mut() {
        if let Some(new_name) = tag.pending_rename.take() {
            tag.name = new_name;
        }
    }
    write_board_config(config_path, config)?;

    Ok(())
}
```

### `src-tauri/src/lib.rs` — recovery on startup

Call `apply_pending_renames` at startup, after checking the board exists:

```rust
// In run(), after discovering project_dir and before starting the watcher:
let config_path = project_dir.join("rojekti").join("rojekti.config.yaml");
if config_path.exists() {
    if let Ok(mut config) = storage::read_board_config(&config_path) {
        let has_pending = config.epics.iter().any(|e| e.pending_rename.is_some())
            || config.tags.iter().any(|t| t.pending_rename.is_some());
        if has_pending {
            if let Err(e) = storage::apply_pending_renames(&project_dir, &mut config, &config_path) {
                eprintln!("[warn] Failed to recover pending rename: {}", e);
            }
        }
    }
}
```

### `src-tauri/src/commands.rs` — hook into save_board_config

In `save_board_config`, detect renames by comparing old and new config. A rename is when an epic/tag exists in both old and new config at the same position but with a different name (position-stable rename detection):

```rust
// After acquiring write_lock, load old config:
let old_config = storage::read_board_config(&config_path)?;

// Detect renames: same index, different name
for (i, new_epic) in config.epics.iter().enumerate() {
    if let Some(old_epic) = old_config.epics.get(i) {
        if old_epic.name != new_epic.name {
            storage::rename_epic_or_tag(
                &state.project_dir,
                &mut config,
                true,
                &old_epic.name,
                &new_epic.name,
                &config_path,
            )?;
        }
    }
}
// Same for tags
```

## Frontend Changes

The frontend sends the full updated config to `save_board_config` as it does today. No changes needed in the Vue components — rename detection happens entirely in Rust by comparing old and new config.

`pendingRename` should be stripped from the `Epic`/`Tag` TypeScript types or marked as optional — it should never be sent from the frontend, only set by the backend:

```ts
export interface Epic {
  name: string
  color: string
  pendingRename?: string // read-only, set by backend during rename
}
```

---

## Constraints

- Epics and tag names must be unique within their respective lists — validated in `BoardSettingsModal.vue` on save
- Do not rename an epic/tag to a name that already exists in the list — the uniqueness check in the frontend covers this
- Do not reorder epics/tags in the same save operation as a rename — the position-stable rename detection assumes index parity between old and new config
