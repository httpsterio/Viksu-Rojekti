## Overview

A board-level setting that marks one or more statuses as "done". Cards in a done status are considered finished — no changes to card files, just a config-level classification that other features read from.

## Config

Add `doneStatuses` to `BoardConfig` — a list of **status IDs** (not names):

```yaml
doneStatuses:
  - f2d7fc66-f104-4bed-83b8-9c79a4232273
```

Using IDs means renames are free — the ID doesn't change when the name does, so no special rename propagation is needed. `#[serde(default)]` on the Rust field handles backward compatibility with existing configs — it will be written as an empty list on first save. `doneStatuses: string[]` in the TypeScript interface (not optional — always present).

Default on init: the ID of the last status in the default list (`Done`). This must be set in both `commands.rs` and `cli.rs` when generating the initial config — capture the UUID of the last status after creating it and place it in `done_statuses`. Empty list is valid — no statuses are considered done.

## UI

A new section in Board Settings, separate from the status order/rename editor. A single MultiSelect showing all current status names (display names only — IDs are internal). Users pick 0–n. Saved as part of the config on save.

The MultiSelect options come from `config.statuses`. Use `optionValue="id"` and `optionLabel="name"` — PrimeVue handles the mapping automatically. The bound array will contain only UUID strings; the user sees only human-readable names.

## Deletion cleanup

When a status is deleted and the user saves settings, any of its IDs present in `doneStatuses` must be removed before saving. This follows the same pattern as stale filter cleanup in `saveBoardConfig` in `useBoard.ts` — strip entries from `newConfig.doneStatuses` whose IDs are no longer present in `newConfig.statuses`, then call `invoke`. No backend logic needed.

## Effects

Other features read `doneStatuses` to determine card done-ness:

- **Board view** — lanes can be hidden from view independently of done status (roj-024)
- **Epic view** — done cards collapsed at the bottom of each epic (roj-045)
- Potentially: faded styling on cards in done statuses on the main board
