# Spec: Priority System

## Overview

Priorities are stored as integers 0–5 on card files. 0 means no priority. 1 is the most urgent, 5 is the least. The config holds exactly 5 `Priority { name, color }` objects — their position in the array is their identity, so renaming never touches card files.

roj-014 (card border colors) is resolved as part of this ticket.

---

## Data model

### `src-tauri/src/models.rs`

Add a `Priority` struct:

```rust
#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct Priority {
    pub name: String,
    pub color: String,
}
```

Change `BoardConfig.priorities` from `Vec<String>` to `Vec<Priority>`.

Change `CardMeta.priority` from `String` to `u8`, with a custom deserializer that accepts any YAML value and returns 0 for anything that is not a valid integer in the range 1–5:

```rust
#[serde(deserialize_with = "deserialize_priority")]
pub priority: u8,
```

```rust
fn deserialize_priority<'de, D>(deserializer: D) -> Result<u8, D::Error>
where
    D: serde::Deserializer<'de>,
{
    let value = serde_yaml::Value::deserialize(deserializer)?;
    let n = match value {
        serde_yaml::Value::Number(n) => n.as_u64().unwrap_or(0),
        serde_yaml::Value::String(s) => s.trim().parse::<u64>().unwrap_or(0),
        _ => 0,
    };
    if n >= 1 && n <= 5 { Ok(n as u8) } else { Ok(0) }
}
```

This covers integers, quoted integers (e.g. `"4"`), strings, arrays, nulls, out-of-range values, and missing fields — all become 0.

## What not to do

- Do not add rename detection in `save_board_config` for priorities — names are display-only, position is identity
- Do not allow adding or removing priority levels — the list is always exactly 5
- Do not validate name uniqueness — priority names are just labels
