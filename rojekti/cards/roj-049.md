# Spec: Replace SortableJS with FormKit Drag-and-Drop

## Overview

SortableJS requires `forceFallback: true` in WebView2 (Tauri on Windows) because WebView2 renders the HTML5 drag ghost outside the DOM — it can't be styled or hidden, and `dragover` events fire inconsistently. `forceFallback: true` works around this by switching to pointer/mouse events, but the visual result is still janky.

This replaces SortableJS with `@formkit/drag-and-drop`, which has a `nativeDrag: false` option that does the same pointer-event fallback but with full control over the drag visual. It's also Vue-native via a `useDragAndDrop` composable.

**API reference:** `DOCS/FORMKIT-DOCS.md`

---

## Packages

```
npm install @formkit/drag-and-drop
```

Remove `sortablejs` and `@types/sortablejs` once both phases are verified working in the Tauri window.

---

## Shared config defaults

Both phases use these options:

```ts
import { useDragAndDrop, animations } from "@formkit/drag-and-drop"

{
  nativeDrag: false,         // pointer events instead of HTML5 DnD — required for WebView2
  plugins: [animations()],   // FLIP animation when items reorder (replaces SortableJS animation: 150)
}
```

## Phase 1: `BoardSettingsModal.vue`

Three lists — statuses, epics, tags — each with y-axis-only reordering via a drag handle. No cross-list dragging.

### What changes

Remove: `initSortable`, all three `Sortable` instances and their refs (`statusesContainer`, `epicsContainer`, `tagsContainer`), the `onShow` handler, and the SortableJS import.

Replace with three `useDragAndDrop` calls, set up inside `watch(visible)` (since localConfig is only populated when the modal opens).

### Setup

```ts
import { useDragAndDrop, animations } from "@formkit/drag-and-drop"
import { watch } from "vue"

const [statusesParent, statusValues] = useDragAndDrop<BoardConfig["statuses"][number]>([], {
  nativeDrag: false,
  dragHandle: ".drag-handle",
  plugins: [animations()],
  onSort: ({ values }) => {
    if (localConfig.value) localConfig.value.statuses = values
  },
})

const [epicsParent, epicValues] = useDragAndDrop<BoardConfig["epics"][number]>([], {
  nativeDrag: false,
  dragHandle: ".drag-handle",
  plugins: [animations()],
  onSort: ({ values }) => {
    if (localConfig.value) localConfig.value.epics = values
  },
})

const [tagsParent, tagValues] = useDragAndDrop<BoardConfig["tags"][number]>([], {
  nativeDrag: false,
  dragHandle: ".drag-handle",
  plugins: [animations()],
  onSort: ({ values }) => {
    if (localConfig.value) localConfig.value.tags = values
  },
})

watch(visible, (isVisible) => {
  if (isVisible && localConfig.value) {
    statusValues.value = [...localConfig.value.statuses]
    epicValues.value = [...localConfig.value.epics]
    tagValues.value = [...localConfig.value.tags]
  }
})
```

No `group` option — each list is isolated, items cannot be dragged between them.

### Template changes

Attach the `parent` refs to the list containers and iterate `values` instead of `localConfig.*`:

```vue
<div :ref="statusesParent" class="list-editor">
  <div v-for="(status, index) in statusValues" :key="status.id" class="list-item">
    ...
  </div>
</div>

<div :ref="epicsParent" class="list-editor">
  <div v-for="(epic, index) in epicValues" :key="epic.name" class="list-item">
    ...
  </div>
</div>

<div :ref="tagsParent" class="list-editor">
  <div v-for="(tag, index) in tagValues" :key="tag.name" class="list-item">
    ...
  </div>
</div>
```

The `@show="onShow"` handler on `<Dialog>` is removed. The `watch(visible)` above handles init.

### CSS

No new classes needed. `animations()` handles the FLIP transition internally. The existing `.drag-handle { cursor: grab }` stays.

## Phase 2: `Lane.vue`

Cards can be dragged within a lane (reorder) or across lanes (move to different status).

### What changes

Remove: `initSortable`, the `sortable` instance, `onMounted`/`onUnmounted`/`watch` that manage it, SortableJS import, and the `:deep(.ghost-card)` and `:deep(.dragging-card)` CSS rules.

### Setup

```ts
import { useDragAndDrop, animations } from "@formkit/drag-and-drop"
import { watch } from "vue"

const [cardParent, cardValues] = useDragAndDrop<CardType>(props.cards, {
  nativeDrag: false,
  group: "cards",
  plugins: [animations()],
  draggingClass: "dragging-card",
  dragPlaceholderClass: "ghost-card",
  onSort: ({ values }) => {
    const card = values[values.indexOf(/* moved card */)]
    // see position calculation below
  },
  onTransfer: ({ values, draggedValue }) => {
    // cross-lane drop — see position calculation below
  },
})

watch(() => props.cards, (cards) => {
  cardValues.value = cards
})
```

The `watch` on `props.cards` keeps FormKit in sync when the board reloads from disk (e.g. after a save).

The `disabled` option mirrors the existing collapsed check:

```ts
const [cardParent, cardValues] = useDragAndDrop<CardType>(props.cards, {
  ...
  disabled: props.collapsed,
})
```

Watch `props.collapsed` and call `updateConfig({ disabled: isCollapsed })` (third return value from `useDragAndDrop`).

### Template

```vue
<div :ref="cardParent" class="lane-body" :data-status-id="id">
  <Card v-for="card in cardValues" :key="card.id" :card="card" :data-pos="card.position" />
</div>
```

### Position calculation

`onSort` and `onTransfer` both receive the updated `values` array in the new order. Use the array index to compute fractional midpoint positions, replacing the DOM walk:

```ts
const calcPosition = (values: CardType[], index: number): number => {
  if (values.length === 1) return 1.0
  if (index === 0) return values[1].position / 2
  if (index === values.length - 1) return values[index - 1].position + 1.0
  return (values[index - 1].position + values[index + 1].position) / 2
}
```

```ts
onSort: ({ values, draggedValue }) => {
  const index = values.indexOf(draggedValue)
  const newPos = calcPosition(values, index)
  moveCard(draggedValue.id, props.id, newPos)
},
onTransfer: ({ values, draggedValue }) => {
  const index = values.indexOf(draggedValue)
  const newPos = calcPosition(values, index)
  moveCard(draggedValue.id, props.id, newPos)
},
```

Note: `onTransfer` fires on the **receiving** lane, so `props.id` is the new statusId.

### CSS

Replace the removed `:deep()` rules with scoped equivalents:

```css
:deep(.ghost-card) {
  opacity: 0.4;
  background: var(--color-accent-subtle) !important;
  border: 2px dashed var(--color-accent) !important;
}

:deep(.dragging-card) {
  cursor: grabbing !important;
  box-shadow: 0 10px 20px rgba(0, 0, 0, 0.2) !important;
}
```

The visual behavior is better than the SortableJS version because FormKit renders its own clone element in the DOM, meaning the drag preview follows the cursor cleanly without needing `forceFallback`.

---

## What not to do

- Do not add cross-list dragging in BoardSettingsModal — statuses, epics, and tags are separate lists
- Do not remove SortableJS until both phases are verified working in the Tauri window
- Do not use `nativeDrag: true` (the default) — WebView2 does not support HTML5 DnD reliably
