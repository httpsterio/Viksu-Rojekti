# Spec: Replace SortableJS with Pragmatic DnD

## Overview

SortableJS requires `forceFallback: true` in WebView2 (Tauri on Windows), which limits visual control over the drag experience — the dragged element doesn't follow the mouse cleanly, and the ghost placeholder can't be styled reliably. This replaces SortableJS with `@atlaskit/pragmatic-drag-and-drop`, which uses pointer events and gives full control over drag previews and drop indicators.

**WebView2 risk:** pragmatic uses the HTML5 Drag and Drop API internally. If WebView2 doesn't support it (same root cause as the SortableJS issue), the implementation won't work. Verify with a single draggable item in BoardSettingsModal before proceeding with the full implementation.

---

## Packages

```
npm install @atlaskit/pragmatic-drag-and-drop @atlaskit/pragmatic-drag-and-drop-hitbox
```

- `@atlaskit/pragmatic-drag-and-drop` — core: `draggable()`, `dropTargetForElements()`
- `@atlaskit/pragmatic-drag-and-drop-hitbox` — closest edge detection (above/below an item)

Remove `sortablejs` and `@types/sortablejs` once both phases are working.

## Phase 1: `BoardSettingsModal.vue`

Three lists — statuses, epics, tags — each with y-axis-only reordering via a drag handle. No cross-list dragging.

### What changes

Remove the `initSortable` function, all `Sortable` instances, the `onShow` handler that initialises them, and the SortableJS import.

Replace with pragmatic bindings set up in `onMounted` (or `watch(visible)` since the modal is conditionally rendered).

### Per-item setup

Each `.list-item` element needs two bindings:

**Draggable** — attached to the drag handle element:
```ts
draggable({
  element: handleEl,
  getInitialData: () => ({ listType, index }),
})
```

**Drop target** — attached to the list item element:
```ts
dropTargetForElements({
  element: itemEl,
  getData: ({ input, element }) =>
    attachClosestEdge({ listType, index }, { input, element, allowedEdges: ['top', 'bottom'] }),
  canDrop: ({ source }) => source.data.listType === listType,
  onDrag: ({ self }) => { closestEdge = extractClosestEdge(self.data) },
  onDrop: ({ source, self }) => {
    const from = source.data.index
    const edge = extractClosestEdge(self.data)
    const to = edge === 'bottom' ? self.data.index + 1 : self.data.index
    reorder(listType, from, to)
  },
})
```

`reorder` does the same splice logic as the current SortableJS `onEnd`:
```ts
const reorder = (list: 'statuses' | 'epics' | 'tags', from: number, to: number) => {
  if (!localConfig.value || from === to) return
  const items = localConfig.value[list]
  const item = items.splice(from, 1)[0]
  items.splice(to > from ? to - 1 : to, 0, item as any)
}
```

### Drop indicator

Show a thin horizontal line above or below the target item during drag. Add a `<div class="drop-indicator">` inside each `.list-item`, shown only when that item is the active drop target:

```vue
<div class="drop-indicator top" v-if="closestEdge === 'top'" />
<div class="drop-indicator bottom" v-if="closestEdge === 'bottom'" />
```

```css
.drop-indicator {
  height: 2px;
  background: var(--color-accent);
  border-radius: 1px;
  pointer-events: none;
}
.drop-indicator.top { margin-bottom: -2px; }
.drop-indicator.bottom { margin-top: -2px; }
```

### Smooth reorder animation

Wrap each list with Vue's `<TransitionGroup>` and add a `.list-move` CSS rule. When the array is reordered after a drop, Vue animates the items into their new positions using FLIP internally:

```vue
<TransitionGroup name="list" tag="div" class="list-editor">
  <div v-for="(status, index) in localConfig.statuses" :key="status.id" class="list-item">
  ...
</TransitionGroup>
```

```css
.list-move {
  transition: transform 0.15s ease;
}
```

## Phase 2: `Lane.vue`

Cards can be dragged within a lane (reorder) or across lanes (move to different status). Each lane body is a drop target. Each card is draggable.

### What changes

Remove `initSortable`, all `Sortable` instances, the SortableJS import, and the `.ghost-card` / `.dragging-card` CSS.

### Card draggable setup

```ts
draggable({
  element: cardEl,
  getInitialData: () => ({ cardId: card.id, fromStatus: props.id }),
})
```

### Lane drop target setup

```ts
dropTargetForElements({
  element: laneBodyEl,
  getData: () => ({ statusId: props.id }),
  canDrop: ({ source }) => !!source.data.cardId,
  onDrop: ({ source, location }) => {
    // determine position from sibling card elements and drop location
    // then call moveCard(cardId, newStatusId, newPos)
  },
})
```

Position calculation on drop: same fractional midpoint logic as the current SortableJS `onEnd`. Walk the lane's card elements, find the closest card to the drop point using the Y coordinates from `location.current.input`, and calculate `newPos` accordingly.

### Drag preview

Use `setCustomNativeDragPreview` to render a compact card clone that follows the cursor:

```ts
draggable({
  element: cardEl,
  getInitialData: () => ({ cardId: card.id, fromStatus: props.id }),
  onGenerateDragPreview: ({ nativeSetDragImage }) => {
    setCustomNativeDragPreview({
      nativeSetDragImage,
      render: ({ container }) => {
        // append a styled card clone to container
      },
    })
  },
})
```

### Drop indicator

Show a horizontal line between cards at the target drop position, same approach as Phase 1.

### Smooth reorder animation

Same `<TransitionGroup>` + `.list-move` approach on the cards list within each lane.

## What not to do

- Do not implement cross-list dragging in BoardSettingsModal — statuses, epics, and tags are separate lists and items must stay within their own list
- Do not remove SortableJS until both phases are verified working in the Tauri window
- Do not skip the WebView2 proof-of-concept before writing implementation code
