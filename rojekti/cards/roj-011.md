# Feature Spec: Real-Time File Watcher

## Overview

Rojekti is a local-first Kanban board built with Tauri 2 (Rust backend + Vue 3 frontend). Cards are stored as
Markdown files with YAML frontmatter. The board can be manipulated via both the GUI and a CLI (the same
executable accepts CLI args). When an external process edits board files (CLI, text editor, a second GUI
instance), the open GUI has no knowledge of those changes. This spec describes the implementation of a
cross-platform file watcher that detects external changes and triggers a full board reload in the GUI.

### `commands.rs` — All write commands (relevant for loop prevention)

Every write command acquires `state.write_lock` before touching the filesystem. The commands that write
files are: `create_card`, `update_card`, `delete_card`, `move_card`, `reorder_status`,
`save_board_config`, `init_project`. Example:

```rust
#[tauri::command]
pub fn update_card(card: Card, state: State<AppState>) -> Result<Card, String> {
    let _lock = state.write_lock.lock().map_err(|e| format!("Lock error: {}", e))?;
    storage::write_card(&state.project_dir, &card)?;
    index::rebuild_index(&state.project_dir)?;
    Ok(card)
}
```

Note: `index::rebuild_index()` is called after every write. It writes `rojekti.index.yaml`. This file
must be ignored by the watcher (see below).

### `useBoard.ts` — `loadBoard()` and the loading overlay

see the board disappear and reappear every time they interact with it.

## Design Decisions

| Question | Decision | Reason |
|---|---|---|
| What to watch? | Entire `rojekti/` folder, recursively | Covers cards, config, and future attachments folder |
| Debounce location | Rust backend | Reduces bridge traffic; single 5-second timer reset per burst |
| Loop prevention | Required — suppress events from GUI writes | `isLoading` shows a full-screen overlay; GUI writes must not trigger reload |
| Loop prevention mechanism | `last_gui_write: Arc<Mutex<Instant>>` in AppState | Updated before every GUI file write; watcher checks it |
| Suppression window | 7 seconds | Debounce is 5s + 2s buffer to avoid race at boundary |
| Event payload | Empty ping (`board-changed`) | Frontend always does a full `loadBoard()`; no partial state updates |
| Watcher crate | `notify` v6, `RecommendedWatcher` | Native APIs on all platforms (inotify/FSEvents/ReadDirectoryChangesW) |
| Ignore `rojekti.index.yaml` | Yes — filter it out in watcher thread | It is auto-generated on every write; never read by `loadBoard()`; would cause double-events |
| Watcher start — board exists | In `setup()` hook | Board dir already present at launch |
| Watcher start — after init | In `init_project` command via `AppHandle` | Dir doesn't exist until init runs |
| Watcher storage | `Mutex<Option<RecommendedWatcher>>` in `AppState` | Must be kept alive for duration of app; `Option` because it may start later |

## Implementation Steps

### Step 1 — Add the `notify` dependency

In `src-tauri/Cargo.toml`, add:

```toml
notify = "6"
```

### Step 2 — Update `AppState` in `models.rs`

Add two fields to `AppState`:

```rust
use std::sync::{Arc, Mutex};
use std::time::Instant;

pub struct AppState {
    pub project_dir: std::path::PathBuf,
    pub write_lock: Mutex<()>,
    pub last_gui_write: Arc<Mutex<Instant>>,
    pub watcher: Mutex<Option<notify::RecommendedWatcher>>,
}
```

`last_gui_write` tracks when the GUI last wrote a file. The watcher thread reads it to decide whether to
suppress an event. `watcher` holds the live watcher so it is not dropped.

### Step 3 — Create `src-tauri/src/watcher.rs`

Create a new module. This is the core of the feature.

```rust
use notify::{RecommendedWatcher, RecursiveMode, Watcher, Event, EventKind};
use std::path::PathBuf;
use std::sync::{Arc, Mutex};
use std::time::{Duration, Instant};
use tauri::{AppHandle, Emitter};

const DEBOUNCE_SECS: u64 = 5;
const SUPPRESS_SECS: u64 = 7;

pub fn start(
    project_dir: PathBuf,
    app_handle: AppHandle,
    last_gui_write: Arc<Mutex<Instant>>,
) -> Result<RecommendedWatcher, String> {
    let watch_dir = project_dir.join("rojekti");

    let (tx, rx) = std::sync::mpsc::channel::<Result<Event, notify::Error>>();

    let mut watcher = RecommendedWatcher::new(
        move |res| { let _ = tx.send(res); },
        notify::Config::default(),
    ).map_err(|e| format!("Failed to create watcher: {}", e))?;

    watcher
        .watch(&watch_dir, RecursiveMode::Recursive)
        .map_err(|e| format!("Failed to watch directory: {}", e))?;

    std::thread::spawn(move || {
        loop {
            // Block until first event arrives
            match rx.recv() {
                Err(_) => break, // sender dropped, app is shutting down
                Ok(event) => {
                    if should_ignore(&event) {
                        continue;
                    }
                    // Drain subsequent events for up to DEBOUNCE_SECS with resets
                    loop {
                        match rx.recv_timeout(Duration::from_secs(DEBOUNCE_SECS)) {
                            Ok(next_event) => {
                                if !should_ignore(&next_event) {
                                    // Another real change arrived — reset the debounce window
                                    continue;
                                }
                            }
                            Err(_) => break, // timeout: no events for 5 seconds — fire
                        }
                    }

                    // Check if the GUI was the writer
                    let suppress = {
                        let t = last_gui_write.lock().unwrap();
                        t.elapsed() < Duration::from_secs(SUPPRESS_SECS)
                    };

                    if !suppress {
                        let _ = app_handle.emit("board-changed", ());
                    }
                }
            }
        }
    });

    Ok(watcher)
}

fn should_ignore(event: &Result<Event, notify::Error>) -> bool {
    let event = match event {
        Ok(e) => e,
        Err(_) => return true,
    };

    // Only care about data modifications (not access times, metadata, etc.)
    match event.kind {
        EventKind::Modify(_) | EventKind::Create(_) | EventKind::Remove(_) => {}
        _ => return true,
    }

    // Ignore the auto-generated index file and editor temp files
    for path in &event.paths {
        let name = path.file_name().and_then(|n| n.to_str()).unwrap_or("");
        if name == "rojekti.index.yaml"
            || name.ends_with(".tmp")
            || name.ends_with(".swp")
            || name.starts_with('.')
        {
            return true;
        }
    }

    false
}
```

**Notes on the debounce loop**: The inner `loop` drains events using `recv_timeout`. Each time a
non-ignored event arrives before the timeout, `continue` resets the 5-second window. When no event
arrives within 5 seconds, `break` exits the drain loop and the code proceeds to check suppression and
emit.

### Step 4 — Update `lib.rs`

Declare the new module and update `AppState` initialization and `setup()`:

```rust
pub mod watcher; // add this alongside the existing mod declarations

pub fn run() {
    let project_dir = discover_project_dir().unwrap_or_else(|| {
        std::env::current_dir().unwrap_or_default()
    });

    let last_gui_write = std::sync::Arc::new(std::sync::Mutex::new(std::time::Instant::now()));

    tauri::Builder::default()
        .manage(AppState {
            project_dir: project_dir.clone(),
            write_lock: std::sync::Mutex::new(()),
            last_gui_write: last_gui_write.clone(),
            watcher: std::sync::Mutex::new(None),
        })
        .setup(move |app| {
            if let Some(window) = app.get_webview_window("main") {
                let _ = window.show();
            }

            // Start the watcher immediately if the board already exists
            let rojekti_dir = project_dir.join("rojekti");
            if rojekti_dir.exists() {
                let state: tauri::State<AppState> = app.state();
                match watcher::start(project_dir.clone(), app.handle().clone(), last_gui_write.clone()) {
                    Ok(w) => {
                        *state.watcher.lock().unwrap() = Some(w);
                    }
                    Err(e) => eprintln!("Watcher failed to start: {}", e),
                }
            }

            Ok(())
        })
        .invoke_handler(tauri::generate_handler![
            commands::get_board_config,
            commands::save_board_config,
            commands::get_all_cards,
            commands::get_card,
            commands::create_card,
            commands::update_card,
            commands::delete_card,
            commands::move_card,
            commands::reorder_status,
            commands::rebuild_index,
            commands::init_project,
        ])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

### Step 5 — Update `commands.rs`: loop prevention

Add `last_gui_write` stamping to every command that writes files. Do this at the top of the write
operation, inside the `write_lock` scope but before the actual file write:

```rust
// Helper macro or inline — add this line inside write_lock scope in each write command:
*state.last_gui_write.lock().map_err(|e| format!("Lock error: {}", e))? = std::time::Instant::now();
```

Commands that need this stamp: `create_card`, `update_card`, `delete_card`, `move_card`,
`reorder_status`, `save_board_config`, `init_project`.

Example — `update_card` after the change:

```rust
#[tauri::command]
pub fn update_card(card: Card, state: State<AppState>) -> Result<Card, String> {
    let _lock = state.write_lock.lock().map_err(|e| format!("Lock error: {}", e))?;
    *state.last_gui_write.lock().map_err(|e| format!("Lock error: {}", e))? = std::time::Instant::now();
    storage::write_card(&state.project_dir, &card)?;
    index::rebuild_index(&state.project_dir)?;
    Ok(card)
}
```

Apply the same pattern to all other write commands.

### Step 6 — Update `init_project` command to start the watcher

`init_project` creates the `rojekti/` folder for the first time. After it does, the watcher needs to
start. Add `app_handle: tauri::AppHandle` as a parameter:

```rust
#[tauri::command]
pub fn init_project(
    name: String,
    prefix: String,
    app_handle: tauri::AppHandle,
    state: State<AppState>,
) -> Result<(), String> {
    let _lock = state.write_lock.lock().map_err(|e| format!("Lock error: {}", e))?;
    *state.last_gui_write.lock().map_err(|e| format!("Lock error: {}", e))? = std::time::Instant::now();

    // ... existing init logic unchanged ...

    // Start the watcher now that the directory exists
    let mut watcher_guard = state.watcher.lock().map_err(|e| format!("Lock error: {}", e))?;
    if watcher_guard.is_none() {
        match crate::watcher::start(state.project_dir.clone(), app_handle, state.last_gui_write.clone()) {
            Ok(w) => { *watcher_guard = Some(w); }
            Err(e) => eprintln!("Watcher failed to start after init: {}", e),
        }
    }

    Ok(())
}
```

### Step 7 — Frontend: listen for `board-changed` in `App.vue`

Add a Tauri event listener in `onMounted`, after the initial `loadBoard()`:

```typescript
import { listen } from '@tauri-apps/api/event'

onMounted(async () => {
    await loadBoard()
    listen('board-changed', () => {
        loadBoard()
    })
})
```

No debounce needed on the frontend — the Rust side already ensures at most one event fires per 5-second
quiet window.

## Coding Conventions to Follow

These are established project rules — do not deviate from them:

- All new structs go in `models.rs`.
- All file I/O stays in `storage.rs`. Do not add filesystem calls anywhere else.
- Error handling: always `Result<T, String>`. No `unwrap()` in command handlers.
- Use `PathBuf` and `.join()` for all paths. No string concatenation.
- Do not use the Tauri filesystem plugin.
- Do not add dependencies without confirming first (the `notify` crate is pre-approved for this feature).
- `#[serde(skip_serializing_if = "Option::is_none")]` on all optional fields.
- `<script setup lang="ts">` in all Vue SFCs.
- No `any` in TypeScript.
- Do not write comments explaining what code does — only comment the "why" when non-obvious.

## What Not to Do

- Do not use `PollWatcher` — native watchers exist on all target platforms.
- Do not watch the parent of `rojekti/` — scope it to `rojekti/` only.
- Do not emit file paths in the event payload — the frontend always does a full `loadBoard()`.
- Do not debounce on the frontend — the Rust side handles it.
- Do not skip the `last_gui_write` suppression — the `isLoading` overlay makes unsuppressed GUI-write
  events produce a visible full-screen flash on every user interaction.
- Do not put watcher initialization inside CLI mode (`main.rs` before Tauri init) — the watcher is
  GUI-only.

## Expected Behaviour After Implementation

| Scenario | Result |
|---|---|
| External CLI edits a card | GUI reloads ~5s after the last change |
| User edits a card file in a text editor and saves | GUI reloads ~5s after save |
| Two GUI instances open on the same board; one makes a change | Other instance reloads within ~5s |
| User updates a card in the GUI | No reload triggered (suppressed for 7s) |
| User drags a card to a new lane | No reload triggered |
| User saves settings (config write) | No reload triggered |
| Rapid external edits (e.g. a script writes 10 cards quickly) | Single reload ~5s after the last write |
| `rojekti.index.yaml` is updated by CLI | Ignored — no reload |
