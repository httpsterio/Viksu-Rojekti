## Approach

Use Cargo's built-in `tests/` directory — no external framework needed. Each file in `tests/` is compiled as its own crate and only sees the public API, which is fine since all functions worth testing are already `pub`. Run with `cargo test` from `src-tauri/`.

```
src-tauri/
  src/
    storage.rs
    models.rs
    ...
  tests/
    storage.rs
    models.rs
  Cargo.toml
```

One file per source module. Tests are separate from production code and don't pollute the source files.

Note: if private functions ever need testing, inline `#[cfg(test)]` blocks inside the source file are the escape hatch — both patterns can coexist.

## Where to start

**`tests/storage.rs` — `parse_card_file` and `serialize_card_file`**

These are the best first targets. They're pure functions: string in, structured data out (or vice versa). No filesystem, no state, nothing to mock.

Things worth testing:
- A valid card parses correctly into the expected `CardMeta` fields
- A card with missing `---` delimiters returns an `Err`
- A card with malformed YAML returns an `Err` with a useful message
- A card with no body (empty string after the second `---`) parses without panicking
- `serialize_card_file` → `parse_card_file` round-trips without data loss

**`tests/storage.rs` — `ensure_ids`**

Added as part of the stable ID system (roj-068). This function assigns UUID v4 to any `Epic`, `Tag`, or `Status` in `BoardConfig` whose `id` field is empty, and returns `true` if any IDs were assigned. It's a pure function and a high-priority test target because silent migration correctness matters.

Things worth testing:
- A config where all entries already have IDs: `ensure_ids` returns `false` and no IDs change
- A config where some entries have empty IDs: those entries get non-empty UUIDs assigned, others are untouched, returns `true`
- A config where all entries have empty IDs: all get assigned, returns `true`
- IDs assigned are non-empty and unique across the call

Note: `ensure_ids` requires the `uuid` crate (already a dependency in `Cargo.toml`). No additional setup needed.

**`tests/storage.rs` — `read_board_config` / `write_board_config` round-trip**

Separate from the card file round-trip above. The config round-trip must verify that `id` fields on `Epic`, `Tag`, and `Status` survive serialization and deserialization intact. Also verify backward compatibility: a legacy `rojekti.config.yaml` without `id` fields should parse without error (the `#[serde(default)]` on those fields handles this, but it should be pinned as a regression test).

**`tests/models.rs` — `deserialize_priority`**

The custom priority deserializer has branching logic worth pinning:
- Priority `3` (number) deserializes to `3`
- Priority `"3"` (string) deserializes to `3`
- Priority `0` or `6` (out of range) deserializes to `0`
- Missing priority field uses the `#[serde(default)]` zero value

## How to add a test (example)

```rust
// tests/storage.rs
use rojekti::storage::parse_card_file;

#[test]
fn parse_card_file_valid() {
    let content = "---\nid: roj-001\ntitle: Test card\nstatus: backlog\ntags: []\npriority: 3\nposition: 1.0\ncreated: 2026-01-01\n---\n\nBody text here";
    let (meta, body) = parse_card_file(content).unwrap();
    assert_eq!(meta.id, "roj-001");
    assert_eq!(meta.priority, 3);
    assert_eq!(body, "Body text here");
}

#[test]
fn parse_card_file_missing_delimiters() {
    let result = parse_card_file("no frontmatter here");
    assert!(result.is_err());
}
```

## What to skip for now

- `read_card`, `write_card`, `list_card_files` — these hit the filesystem and would need `tempdir` or similar setup. Not worth it yet.
- `apply_pending_renames` — multi-step, filesystem-dependent, better tested manually for now.
- Anything in `commands.rs` — those functions all take `tauri::State` and are only callable through the IPC layer.
