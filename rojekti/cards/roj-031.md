## Overview

Store ephemeral user preferences in a separate state file, distinct from `rojekti.config.yaml`. Config is project-level and worth version-controlling. State is local and disposable — if deleted, the app regenerates it with defaults on next launch with no data loss.

## File

`rojekti/rojekti.state.yaml` — adjacent to the config file.

## Contents

```yaml
theme: dark
collapsedStatuses:
  - DONE
  - ARCHIVE
hiddenStatuses: []
activeFilters:
  epic: null
  tag: null
  priority: null
  search: ""
language: en
audioVolume: 0.5
customCursorsEnabled: false
```

`hiddenStatuses` mirrors what's in the config (roj-024) — included here so the "Show hidden" toggle state can be persisted per-session if needed, but the source of truth for which statuses are hidden lives in config.

## Behaviour

- Loaded on startup in parallel with config and cards
- Written whenever theme, collapsed lanes, active filters (epic/tag/priority), or current view changes
- Search query is NOT persisted — it's a throwaway action
- If the file is missing or fails to parse, silently fall back to defaults — never block startup
- Version-controlled (not gitignored) — state is considered part of the board

## Watcher

Switch the file watcher from a blacklist to a whitelist. Only these paths trigger a board reload:

- `rojekti/cards/*.md`
- `rojekti/deleted/*.md`
- `rojekti/rojekti.config.yaml`

Everything else (state file, index file, tmp files) is ignored by default.

## Implementation notes

**What was actually implemented vs. the original spec:**
- `hiddenStatuses`, `language`, `audioVolume`, `customCursorsEnabled` were left out — they belong to features that don't exist yet. The struct only contains fields that are actively used.
- State is version-controlled, not gitignored. The original spec said ephemeral/disposable; the decision was reversed — state is considered part of the board and worth tracking.
- Search is not persisted (was in the original spec). Restoring a stale search string across restarts is more surprising than useful.

**Watcher refactor:**
The original blacklist approach (`should_ignore`) was replaced with a whitelist (`is_watched`). The blacklist required every new file to be manually added to the ignore list or it would trigger spurious reloads — `rojekti.state.yaml` itself would have caused a reload loop under the old approach. The whitelist inverts this: anything not explicitly listed is ignored by default.

**Vue watcher gotcha:**
Inside async functions, Vue loses component instance tracking across `await` boundaries. Direct ref watching (`watch(ref, cb)`) can silently fail to trigger in this context. All watchers use getter functions (`() => ref.value`) instead — this forces reactive re-evaluation and works correctly regardless of async context. Dark mode was broken until this was fixed; collapsed lanes worked because they already used a getter.
