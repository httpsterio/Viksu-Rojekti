# Spec: Migrate Epics and Tags from ID-based to Name-based

## Overview

Currently epics and tags use opaque timestamp IDs (`epic-1773924443930`, `tag-1773869127764`) stored on card files. This makes raw card files unreadable. This migration replaces IDs with the human-readable name directly on the card.

**Dependency:** This spec must be implemented before roj-034 (Safe Epic/Tag Rename with WAL), which describes the rename safety mechanism that name-based storage requires.

---

## Design

- Cards store the epic/tag **name** directly: `epic: My Feature`, `tags: [Bug, Frontend]`
- Epics and tags in config lose their `id` field — `name` becomes the unique key
- Names must be unique within epics and within tags (enforced in the UI on save)
- Renaming an epic/tag updates all card files (see roj-034 for the safe rename mechanism)
- Deleting a tag or epic from config means **"stop offering it as an option"** — not **"remove it from existing cards"**. Tags and epics on cards are historical facts and must be preserved.

## 2. `src-tauri/src/storage.rs` — one-time migration on read

Add a migration function that detects old-format configs (epics/tags with `id` fields) and rewrites both the card files and config to name-based format.

**Detection:** `LegacyEpic` and `LegacyTag` have `id` as a required field. If the YAML has no `id` on epics/tags (already migrated), deserializing into `LegacyBoardConfig` will fail — the function returns `Ok(())` early. If it succeeds, migration is needed.

Add these structs (private to the module, no `pub`):

```rust
#[derive(Deserialize)]
#[serde(rename_all = "camelCase")]
struct LegacyEpic {
    id: String,
    name: String,
    color: String,
}

#[derive(Deserialize)]
#[serde(rename_all = "camelCase")]
struct LegacyTag {
    id: String,
    name: String,
    color: String,
}

#[derive(Deserialize)]
#[serde(rename_all = "camelCase")]
struct LegacyBoardConfig {
    name: String,
    prefix: String,
    next_id: u32,
    statuses: Vec<crate::models::Status>,
    epics: Vec<LegacyEpic>,
    tags: Vec<LegacyTag>,
    priorities: Vec<String>,
}
```

Migration function:

```rust
pub fn migrate_ids_to_names(dir: &Path) -> Result<(), String> {
    let config_path = dir.join("rojekti").join("rojekti.config.yaml");
    let content = fs::read_to_string(&config_path)
        .map_err(|e| format!("Could not read config: {}", e))?;

    // If this fails, config is already in new format — nothing to do
    let legacy: LegacyBoardConfig = match serde_yaml::from_str(&content) {
        Ok(c) => c,
        Err(_) => return Ok(()),
    };

    // Build ID → name maps
    let epic_map: std::collections::HashMap<String, String> = legacy.epics.iter()
        .map(|e| (e.id.clone(), e.name.clone()))
        .collect();
    let tag_map: std::collections::HashMap<String, String> = legacy.tags.iter()
        .map(|t| (t.id.clone(), t.name.clone()))
        .collect();

    // Rewrite all card files that reference epic/tag IDs
    let files = list_card_files(dir)?;
    for file in files {
        let card_content = fs::read_to_string(&file)
            .map_err(|e| format!("Could not read {}: {}", file.display(), e))?;
        let (mut meta, body) = parse_card_file(&card_content)?;

        let mut changed = false;

        if let Some(epic_id) = &meta.epic {
            if let Some(epic_name) = epic_map.get(epic_id) {
                meta.epic = Some(epic_name.clone());
                changed = true;
            }
        }

        let new_tags: Vec<String> = meta.tags.iter().map(|t| {
            tag_map.get(t).cloned().unwrap_or_else(|| t.clone())
        }).collect();
        if new_tags != meta.tags {
            meta.tags = new_tags;
            changed = true;
        }

        if changed {
            let card = crate::models::Card { meta, body };
            write_card(dir, &card)?;
        }
    }

    // Rewrite config using new Epic/Tag structs (without id)
    let new_config = crate::models::BoardConfig {
        name: legacy.name,
        prefix: legacy.prefix,
        next_id: legacy.next_id,
        statuses: legacy.statuses,
        epics: legacy.epics.iter().map(|e| crate::models::Epic {
            name: e.name.clone(),
            color: e.color.clone(),
        }).collect(),
        tags: legacy.tags.iter().map(|t| crate::models::Tag {
            name: t.name.clone(),
            color: t.color.clone(),
        }).collect(),
        priorities: legacy.priorities,
    };
    write_board_config(&config_path, &new_config)?;

    Ok(())
}
```

## 7. `src/components/CardModal.vue`

- `getTag`: `t.id === id` → `t.name === name`
- `getEpic`: `e.id === id` → `e.name === name`
- Epic `<Select>`: `option-value="id"` → `option-value="name"`
- Tags `<MultiSelect>`: `option-value="id"` → `option-value="name"`

**Orphaned tag/epic handling:** When the modal opens, split the card's tags into known (name exists in `config.tags`) and orphaned (name not found in config). The MultiSelect only binds to known tags. Orphaned tags are displayed as read-only chips below the MultiSelect — the user can remove them manually but they are never silently dropped on save.

```ts
const knownTags = computed(() =>
  card.value.tags.filter(name => config.value?.tags.some(t => t.name === name))
)
const orphanedTags = computed(() =>
  card.value.tags.filter(name => !config.value?.tags.some(t => t.name === name))
)
```

Bind `<MultiSelect>` to `knownTags` (not `card.value.tags` directly). On save, merge back before calling `updateCard`:
```ts
card.value.tags = [...knownTags.value, ...orphanedTags.value]
```

Orphaned tags in the template — shown below the MultiSelect with a neutral style and a remove button:
```vue
<span
  v-for="name in orphanedTags"
  :key="name"
  class="orphaned-tag"
>
  {{ name }} <i class="pi pi-times" @click="removeTag(name)" />
</span>
```

The same logic applies to the epic field: if `card.epic` is set but the name no longer exists in `config.epics`, display it as a read-only label rather than silently clearing it on save.

## What Not to Do

- Do not change `Status` — statuses keep their explicit `id` field
- Do not add a uniqueness constraint at the Rust level — validate in the frontend only
- Do not run the migration if the board hasn't been initialized yet (the `rojekti_dir.exists()` check in `lib.rs` covers this)
- Do not remove orphaned tags or epics from card files when their config entry is deleted — intentional preservation of historical data
- Do not use `any` in TypeScript
- Do not add comments explaining what code does — only comment the "why" when non-obvious
