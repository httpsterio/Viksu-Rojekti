# Task: Graceful Handling of Broken Cards

## Problem

`read_all_cards` in `storage.rs` uses `?` to propagate errors:

```rust
pub fn read_all_cards(dir: &Path) -> Result<Vec<Card>, String> {
    let files = list_card_files(dir)?;
    let mut cards = Vec::new();
    for file in files {
        cards.push(read_card(&file)?);  // <-- short-circuits on first error
    }
    Ok(cards)
}
```

If any single card file has malformed YAML frontmatter (a typo introduced by hand-editing), the entire `get_all_cards` command fails. The frontend catches this as a generic error and the whole board disappears with no useful explanation.

## Fix

Change `read_all_cards` to collect errors per file rather than short-circuit. Broken files are skipped and reported. The rest of the board loads normally.

Return type changes from `Result<Vec<Card>, String>` to `Result<(Vec<Card>, Vec<String>), String>` — a tuple of successfully loaded cards and a list of error messages for failed files.

## Changes Required

### `storage.rs` — update `read_all_cards`

Current:
```rust
pub fn read_all_cards(dir: &Path) -> Result<Vec<Card>, String> {
    let files = list_card_files(dir)?;
    let mut cards = Vec::new();
    for file in files {
        cards.push(read_card(&file)?);
    }
    Ok(cards)
}
```

Replace with:
```rust
pub fn read_all_cards(dir: &Path) -> Result<(Vec<Card>, Vec<String>), String> {
    let files = list_card_files(dir)?;
    let mut cards = Vec::new();
    let mut errors = Vec::new();
    for file in files {
        match read_card(&file) {
            Ok(card) => cards.push(card),
            Err(e) => {
                let filename = file.file_name()
                    .and_then(|n| n.to_str())
                    .unwrap_or("unknown");
                errors.push(format!("Could not load {}: {}", filename, e));
            }
        }
    }
    Ok((cards, errors))
}
```

### `commands.rs` — update all callers of `read_all_cards`

There are two callers:

**1. `get_all_cards`** — the main frontend command. Update to unwrap the tuple and surface errors as toast warnings. The command should still return `Result<Vec<Card>, String>` so the frontend signature doesn't change.

```rust
#[tauri::command]
pub fn get_all_cards(state: State<AppState>) -> Result<Vec<Card>, String> {
    let (cards, errors) = storage::read_all_cards(&state.project_dir)?;
    // errors are returned alongside the cards for the frontend to display
    // For now, log them — the frontend warning mechanism is handled separately (see below)
    for e in &errors {
        eprintln!("[warn] {}", e);
    }
    Ok(cards)
}
```

Wait — the frontend needs to know about the errors to show toasts. The cleanest approach without changing the command signature is to return the errors as a separate field. Change the return type to a struct:

Add to `models.rs`:
```rust
#[derive(serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct AllCardsResult {
    pub cards: Vec<Card>,
    pub errors: Vec<String>,
}
```

Update `get_all_cards` in `commands.rs`:
```rust
#[tauri::command]
pub fn get_all_cards(state: State<AppState>) -> Result<AllCardsResult, String> {
    let (cards, errors) = storage::read_all_cards(&state.project_dir)?;
    Ok(AllCardsResult { cards, errors })
}
```

**2. `create_card`** — uses `read_all_cards` to calculate max position. Update to discard errors silently here (position calculation can proceed with partial card list):

```rust
let (cards, _) = storage::read_all_cards(&state.project_dir)?;
```

### `src/types/index.ts` — add `AllCardsResult` type

```ts
export interface AllCardsResult {
  cards: Card[]
  errors: string[]
}
```

### `src/composables/useBoard.ts` — update `loadBoard` to handle errors

Update the `invoke` call and show a toast per broken file:

```ts
const result = await invoke<AllCardsResult>('get_all_cards')
cards.value = result.cards
for (const error of result.errors) {
  toast.add({ severity: 'warn', summary: 'Could not load card', detail: error, life: 6000 })
}
```

## Notes

- Do not change `read_board_config` — a broken config file should still be a hard failure since there's no board without it
- Do not change the error behaviour in `read_card` itself — it correctly returns `Err` on bad files
- The `AllCardsResult` struct must have `#[serde(rename_all = "camelCase")]` per project conventions
- `severity: 'warn'` (not `'error'`) — the board still loads, it's a non-fatal warning
- `life: 6000` — longer than the standard 3000ms since the user needs time to read the filename
